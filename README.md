# Anonymous AISTATS reproducibility package

This package accompanies the anonymous manuscript on why tying Adam's two momentum parameters, \(\beta_1=\beta_2\), is dynamically special. It contains the code used for the controlled magnitude-variation experiment, the literal discrete decomposition on real Digits gradients, and the six model--dataset training experiments used to measure update-norm oscillations.

The package is intentionally code-only. It excludes datasets, checkpoints, full gradient arrays, raw or aggregated results, rendered figures, logs, credentials, caches, and private audit material. Every excluded artifact is generated by the documented commands.

## Repository layout

| `analysis/train_digits_gradient_trajectory.py` | Trains one full-batch Digits MLP and stores every pre-update gradient. |
| `analysis/literal_decomposition.py` | Computes the full-history discrete \(S+L^{\rm disc}+E\) decomposition for one trajectory. |

## Installation

Python 3.9 or newer is recommended. The exact package versions used for every original server run could not be recovered reliably, so dependencies are intentionally not falsely pinned. The partial environment evidence available to the audit is recorded in [`ENVIRONMENT.md`](ENVIRONMENT.md).

For the deterministic figures, Digits experiment, analysis, and tests:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

For the six full training experiments:

```bash
python -m pip install -r requirements-training.txt
```

The two NanoGPT experiments additionally require a local checkout of the public `karpathy/nanoGPT` repository containing `model.py`, `train.py`, `sample.py`, and `config/`. Set `NANOGPT_ROOT` to that checkout. The historical commit was not recorded, so exact cross-version reproduction of those runs cannot be guaranteed.

## Numerical conventions

### Literal discrete decomposition

Each beta pair is trained independently for seeds 0, 1, and 2. The stored array has shape `(1500, 3466)` and dtype `float32`; analysis converts it to `float64`. First moment, second moment, and log-magnitude EMAs start at zero before step 0, use the full past, and use bias correction \(1-\beta^{k+1}\). Adam's epsilon is \(10^{-8}\) outside the square root. Numerically, `log(max(abs(g), float64.tiny))` is used; this makes the recurrence defined at exact zeros, but zero samples remain ineligible for evaluation. After a 200-step burn-in, endpoint \(k\) is valid only when all \(w\) samples from \(k-w+1\) through \(k\) are finite, nonzero, and have the same sign. No coordinate subsampling or magnitude threshold is used.

The percentage columns are global absolute budgets: sums of absolute coordinate-time contributions are normalized by the sum across \(S\), \(L^{\rm disc}\), and \(E\). \(F_2=1-\sum E^2/\sum(R-S)^2\). Cancellation is reported as \(\kappa=(\sum|L^{\rm disc}|+\sum|E|)/\sum|R-S|\). Sign agreement excludes samples where either compared value is exactly zero.

### Training dynamics

The recorded quantity named `updates_norm` is the Euclidean norm of `(parameters_after - parameters_before) / current_learning_rate`, restricted to parameters owned directly by `Linear` and `Conv1d/2d/3d` modules. Consequently it is not an all-parameter norm and, when weight decay is nonzero, it includes the optimizer's weight-decay contribution. The first three epochs are discarded; the retained sequence is smoothed by an EMA initialized at its first retained value. Table 2 uses window 200 and the mean absolute first difference. Table 4 tests windows 1, 10, 100, 200, and 500 and both first and interior second differences. Ties count as diagonal selections; non-finite values are treated as infinity for selection, and a row with no finite configuration is excluded.

## Full-training entry points

The actual code-level protocol is recorded in `configs/experiment_protocols.json`. One local run can be launched as follows:

```bash
EXPERIMENT_MODULE=resnet18_cifar100 BETA1=0.9 BETA2=0.9 SEED=0 \
  bash code/launchers/launch_experiment.sh
```

Available module names are `resnet18_cifar100`, `efficientnet_tinyimagenet`, `t5_squad`, `nanogpt_wikitext`, `nanogpt_slimpajama`, and `vit_cifar100`. Every entry point also supports `--smoke-test`, but smoke tests may still download models or datasets and are not substitutes for full reproduction.

The supplied SLURM launcher requests one GPU, 8 CPU cores, and 64 GiB RAM by default; these are operational defaults, not measured minima. Original runs used NVIDIA A100-SXM4 80 GB GPUs, with up to three runs active concurrently. Storage needs are dominated by downloaded datasets and raw step histories.

## Fidelity notes

The public code preserves executed logic rather than silently changing it to match labels:

- The manuscript correctly reports EfficientNet-V2-S. Some historical result and figure filenames still contain `EfficientNet-B0`; these names are retained only so the archived-input configuration continues to resolve the original files. The executed constructor is TorchVision `efficientnet_v2_s`.
- In that EfficientNet entry point, sinusoidal initialization is applied before the classifier is replaced; the final 200-class linear head therefore retains PyTorch's default initialization.
- The ViT loader used by the experiment instantiates `vit_b_16` with its default 1000-output classification head, although CIFAR-100 labels occupy only classes 0--99.
- The T5 experiment loads pretrained `t5-small` and then applies the custom initialization only to supported linear/convolutional modules; it is therefore not a clean from-scratch initialization.
- The ResNet script does not explicitly disable TF32, whereas the other five full-training scripts do.
- The NanoGPT learning-rate scheduler advances every 20 optimizer batches while the custom loop is verbose (the first epoch only) and also through the epoch-level callback. This is the executed implementation, not a conventional per-update 20% warm-up.

These facts matter when interpreting or exactly rerunning the published server results. No scientific logic was silently altered in this package.

## Security and provenance

Historical `.pkl` files can be analyzed through `configs/training_sources_legacy.json`, but Python pickle can execute code while loading. Use only trusted files. The preferred fresh-run format is JSON. This package contains no credentials, user paths, Git history, or private raw data.

## Verification scope

During package preparation, the analysis was executed privately against the available original raw results and reproduced every published Table-2 and Table-4 value at displayed precision. Those source results and the regenerated tables are not distributed. Both supported second-difference boundary conventions gave identical Table-4 selection rates. The literal decomposition was executed on one complete 1500-by-3466 trajectory for both the 1000-step and 6-step windows and matched the stored analysis, including exact reconstruction of \(R=S+L^{\rm disc}+E\) to floating-point precision. Lightweight tests and the controlled figure generator are part of the package checks. The costly six-task training grid and full 27-run Digits grid were not rerun during this audit.
