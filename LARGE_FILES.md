# Excluded large artifacts

The distributable intentionally contains no file larger than 25 MiB. Generated datasets and result histories are excluded by `.gitignore`.

| Artifact | How obtained/generated | Required location and format | Consumer | Observed/estimated size and cost |
|---|---|---|---|---|
| Digits gradients | `python analysis/run_digits_grid.py --output-root outputs/digits` | One `gradients.npy` per run, shape `(1500,3466)`, NumPy `float32` | `analysis/literal_decomposition.py` | About 19.8 MiB each; 27 files total, about 535 MiB. CPU-local but 27 trainings take time. |
| Per-run training JSON | Each `code/experiments/*.py` entry point | `outputs/results/<experiment>/runs/*.json`; metadata plus epoch arrays and per-step `updates_norm`, `grads_norm`, and `train_step_loss` | `analysis/analyze_training_dynamics.py` with `configs/training_sources_json.json` | ResNet archive observed at about 462 MiB for 75 files; WikiText at about 408 MiB for 75 files. Other totals depend on step count. GPU server required. |
| Historical merged pickle results | Generated by the older merge pipeline or supplied from trusted archival storage | `raw_results/legacy/<name>.pkl`; top-level protocol fields plus `runs` dictionary keyed by `(beta1,beta2,seed)` | `analysis/analyze_training_dynamics.py` with `configs/training_sources_legacy.json` | Observed: roughly 8--457 MiB per file. Pickles must be trusted. They are not required when fresh JSON runs exist. |
| CIFAR-100 | Downloaded automatically by TorchVision | Under `data/` or `TRAINING_DATA_DIR`; TorchVision CIFAR layout | ResNet18 and ViT loaders | Download archive about 163 MiB, expanded data larger. |
| Tiny ImageNet-200 | Kaggle dataset `xiataokang/tinyimagenettorch` via `kaggle` | `data/tiny-imagenet-200/{train,val}` in `ImageFolder` layout | EfficientNet loader | Several hundred MiB. Requires user-managed Kaggle credentials; the credential file is never distributed. |
| Hugging Face caches | Downloaded by `datasets` and `transformers` | `HF_HOME`, `HF_DATASETS_CACHE`, and related cache directories | T5 and WikiText experiments | Dataset/model dependent; can reach multiple GiB. |
| SlimPajama raw chunk and token bins | Download `train/chunk1/*` and `validation/chunk1/*` from Hugging Face `cerebras/SlimPajama-627B` as shown in `REPRODUCE.md`, then run `python code/runtime_assets/nanogpt_slimpajama_prepare.py` | Raw files under `data/slimpajama-raw/{train,validation}/chunk1/*.jsonl.zst`; output `data/slimpajama/{train,val}.bin` as contiguous native-endian NumPy `uint16` GPT-2 token IDs | Preparation script consumes raw files; NanoGPT SlimPajama loader consumes bins | Depends on selected documents; preparation uses at most 200,000 training and 2,000 validation documents and can require substantial network, disk, and preprocessing time. |
| External nanoGPT checkout | Clone separately from the public `karpathy/nanoGPT` repository | Set `NANOGPT_ROOT`; checkout must contain `model.py`, `train.py`, `sample.py`, `config/` | Both NanoGPT experiments | Small code checkout, but historical commit is unknown. |
| Checkpoints | Optional products of training utilities | `checkpoints/` or user-selected storage | Not needed by the analysis scripts | Potentially hundreds of MiB to several GiB each; not generated by the documented reproduction path. |

No generated CSV or rendered PDF is included: tables, figures, raw arrays, and training histories are all regenerated by the documented commands. No excluded artifact is required without a corresponding generation or acquisition procedure.
